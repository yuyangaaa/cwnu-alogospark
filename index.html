注释是写给人看的说明，编译器会忽略它。单行注释从 // 开始；多行注释放在 /* 和 */ 之间。好的注释说明思路、边界或特殊处理，不必逐字翻译代码。

}

不要在一个 /* ... */ 中再放另一组多行注释。临时屏蔽代码时优先使用编辑器的单行注释快捷键，调试完成后及时清理。

CHAPTER 05 · 给数据一个名字

变量与数据类型

变量可以想象成带名字的盒子：盒子中保存数据，类型决定这个盒子能装什么、能装多大。

variable.cpp
int age = 15;             // 整数
long long score = 10000000000LL; // 大整数
double pi = 3.14159;     // 小数
char grade = 'A';        // 单个字符
bool passed = true;    // 真或假
string name = "Alice";  // 字符串
类型适合保存竞赛中如何选择
int普通整数绝对值不超过约 21 亿
long long很大的整数乘法、总和或答案可能很大时优先考虑
double带小数的数据平均数、几何计算等
char / string单字符 / 一段文字字符题、字符串题

固定小数位数

题目要求“保留若干位小数”时，可以使用 fixed 和 setprecision 控制输出格式。fixed 表示按普通小数形式输出，setprecision(2) 表示小数点后固定保留 2 位。

precision.cpp
#include <iomanip>

double value = 10.0 / 3.0;
cout << fixed << setprecision(2) << value;
运行结果
3.33
i
setprecision 中写的是小数位数

配合 fixed 时，setprecision(3) 会固定保留 3 位小数，例如 2.5 会输出为 2.500。如果省略 fixed，它控制的是有效数字位数，含义不同。

输出格式不会修复整数除法

如果 a 和 b 都是整数，a / b 会先完成整数除法。需要小数结果时，应写成 1.0 * a / b，再使用 fixed 和 setprecision 控制显示位数。

变量怎样命名？

score / maxScore名字表达含义变量名由字母、数字和下划线组成，不能以数字开头。竞赛代码可以简洁，但仍要让自己看得懂。
Score != score区分大小写C++ 严格区分大小写；sum、Sum 和 SUM 是三个不同的名字。
int / for / return关键字不能作为名字语言已经使用的关键字不能再拿来命名变量、函数或结构体。
total_score保持一种风格camelCase 与 snake_case 都可以，重要的是在同一份代码里保持一致。

例如 __value、_Count 通常保留给编译器和标准库。自己写代码时使用 value、count 等普通名称最安全。

不会改变的数据：const 与 constexpr

如果一个值初始化后不应该再被修改，就把它声明为常量。这样既能表达意图，也能让编译器帮你阻止误改。编译期就能确定的常量优先使用 constexpr。

constants.cpp
constexpr int MAX_N = 100000; // 编译期常量
int input;
cin >> input;
const int n = input;              // 运行时读到，但之后不修改

int a[MAX_N + 5];
// n = 20;  // 错误：不能修改 const 变量
i
常量优先于宏

现代 C++ 中通常使用 const 或 constexpr，而不是 #define MAX_N 100000。常量有明确类型，也更容易被编译器检查。

小心整数溢出

100000 * 100000 已超出 int 范围。写成 1LL * 100000 * 100000，或把变量声明为 long long。

运算符

运算符让程序进行数学计算、比较大小并组合条件。它们是后面判断和循环的基础。

+   -   *   /四则运算整数除法会舍去小数部分：7 / 2 得到 3。
%取余数7 % 2 得到 1，常用来判断奇偶。

>   <   >=   <=大小比较注意“大于等于”写作 >=。
&&   ||   !并且 / 或者 / 取反用来组合多个判断条件。

算术运算与整数除法

arithmetic.cpp
int a = 7, b = 2;
cout << a + b << ' ';       // 加法：9
cout << a - b << ' ';       // 减法：5
cout << a * b << ' ';       // 乘法：14

简写赋值与自增自减

int x = 10;

+=、-=、*=、/= 和 %= 都是在原值上计算后再存回变量。单独使用时，++x 与 x++ 都会让 x 加 1；初学阶段不要把它们塞进复杂表达式。

判断一个数是否为偶数

even.cpp
int n;
cin >> n;
cout << (n % 2 == 0);

如果输入 8，表达式 8 % 2 == 0 成立，输出 1；输入 7 时条件不成立，输出 0。

比较与逻辑运算

ticket.cpp
int age;
cin >> age;

bool isTeen = age >= 13 && age <= 18;
bool isFree = age < 6 || age >= 65;
cout << isTeen << ' ' << isFree << ' ';
cout << !isFree;
输入
15
输出
1 0 1

&& 要求两边都成立，|| 只要一边成立，! 会把真假反过来。C++ 默认用 1 表示 true、0 表示 false。

三目运算符：在两个值中选择

条件 ? 条件成立时的值 : 条件不成立时的值 会产生一个结果，适合写简单的二选一。逻辑稍复杂时仍应使用更清晰的 if。

ternary.cpp
int a = 7, b = 12;
int larger = (a > b) ? a : b;
cout << larger;
运行结果
12

位运算：直接处理二进制位

位运算会把整数看成一串二进制位。入门阶段先认识含义即可；学习状态压缩、集合表示或快速幂时会再次用到。

a & b按位与某一位只有在 a、b 对应位置都为 1 时才得到 1，常用于检查某个二进制位。
a | b按位或对应位置只要有一个 1 就得到 1，常用于把某个状态位设为 1。
a ^ b按位异或对应位置不同得到 1、相同得到 0；同一个数异或两次会抵消。
1 << k左移把二进制的 1 向左移动 k 位；在不溢出的非负整数范围内等于 2 的 k 次方。
bits.cpp
int mask = 10;              // 二进制 1010
int k = 1;

bool hasBit = (mask & (1 << k)) != 0;
mask = mask | (1 << 2); // 把第 2 位设为 1
cout << hasBit << ' ' << mask;
位运算不是逻辑运算

&、| 逐位处理整数；&&、|| 判断整个条件的真假。移位只应在位数合法且不会溢出的情况下使用，不要把它机械理解成任何整数都能安全乘除 2。

()
不确定优先级就加括号

* / % 通常先于 + - 计算，例如 2 + 3 * 4 得到 14。培训和比赛中都建议用括号主动表达意图：(2 + 3) * 4 得到 20。

= 和 == 完全不同

x = 5 是把 5 存入 x；x == 5 才是在询问“x 是否等于 5”。这是条件判断中最常见的笔误。

sort_students.cpp
struct Student {
    string name;
    int score;
};

bool better(const Student &a, const Student &b) {
    if (a.score != b.score) return a.score > b.score;
    return a.name < b.name;
}

vector<Student> students = {
    {"Bob", 88}, {"Carol", 97}, {"Alice", 95}
};

sort(students.begin(), students.end(), better);
for (const Student &s : students) {
    cout << s.name << ' ' << s.score << '\n';
}
比较函数不要使用 >= 或 <=

当两个对象完全相等时，比较结果必须为 false，否则排序规则会自相矛盾。需要并列规则时，继续比较另一个成员，最后仍使用严格的 < 或 >。

max、min 与 swap

max 取较大值，min 取较小值，swap 交换两个变量的值。它们能让常见操作写得更直接。

basic_tools.cpp
int a = 8, b = 3;

cout << max(a, b) << ' '; // 较大值
cout << min(a, b) << '\n'; // 较小值

swap(a, b);
cout << a << ' ' << b;
运行结果
8 3
3 8
i
它们是标准库函数，不是 C++ 关键字

使用标准头文件时，max、min 位于 <algorithm>，swap 可由 <utility> 提供。竞赛中常用的 #include <bits/stdc++.h> 已经包含这些头文件。

max 和 min 的两个参数通常要类型一致

例如 max(3, 4LL) 的一个参数是 int、另一个是 long long，可能无法编译。可以写成 max(3LL, 4LL)，让两边类型保持一致。

处理数组和 vector 的常用函数

reverse翻转顺序reverse(a.begin(), a.end()) 将整个 vector 前后颠倒。
count统计出现次数count(a.begin(), a.end(), 3) 统计 3 出现了几次。
find寻找元素找不到时返回 a.end()，使用前要先判断。
max_element寻找最大元素返回元素所在位置，前面加 * 取得数值。
min_element寻找最小元素用法与 max_element 相同。
fill批量赋值fill(a.begin(), a.end(), 0) 把所有元素改成 0。

如果 vector 为空，max_element 会返回 a.end()，此时不能在前面加 *。应先用 a.empty() 判断容器中是否有元素。

模拟

模拟就是让程序按照题目规定的顺序，把一个过程一步一步执行出来。它通常没有难记的公式，真正考查的是：能否把较长的文字规则翻译成明确的状态、操作顺序和边界判断。

识别信号题目反复出现“依次”“每次”“执行操作”“经过若干轮”“最终状态”等描述。

示例：网格中的机器人

给定一张 n 行 m 列的网格、一台机器人的起点 (x, y) 和一串移动指令 s，求机器人执行完所有指令后的坐标。坐标的第一个数是行号，第二个数是列号。左上角为 (1, 1)，行号向下增大，列号向右增大。

机器人从左到右读取 s，每个字符尝试移动一格。U 向上，行号减 1。D 向下，行号加 1。L 向左，列号减 1。R 向右，列号加 1。只有目标格在第 1 到 n 行、第 1 到 m 列之内才移动。越界时留在原格，继续读下一条指令。

输入格式

第一行输入四个整数 n m x y，依次表示行数、列数、起点行号和起点列号。第二行输入指令字符串 s，其中没有空格。

输出格式

输出一行两个整数，以空格分隔，依次为最终的行号和列号。

数据范围

1 ≤ n, m ≤ 10⁹，1 ≤ x ≤ n，1 ≤ y ≤ m。指令数为 1 到 2 × 10⁵，每个字符都是 U、D、L 或 R。

样例中的起点

3 4 2 2 表示网格有 3 行 4 列，机器人从第 2 行第 2 列出发。

样例

输入
3 4 2 2
UURRDDDRU
输出
2 4

先在纸上走一遍

第 2、7、8 条指令尝试走出网格，执行这三条指令时位置保持原样。最后一条 U 从 (3, 4) 移到 (2, 4)，因此输出 2 4。

把单步规则翻译成代码

robot.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m, x, y;
    string s;
    cin >> n >> m >> x >> y >> s;

    // 先试走一步，确认没有越界后再更新位置
    for (char c : s) {
        int nx = x, ny = y;

        if (c == 'U') nx--;
        else if (c == 'D') nx++;
        else if (c == 'L') ny--;
        else if (c == 'R') ny++;

        bool ok = nx >= 1 && nx <= n
                   && ny >= 1 && ny <= m;
        if (ok) {
            x = nx;
            y = ny;
        }
    }
    cout << x << ' ' << y << '\n';
}

为什么先计算 nx、ny？

候选状态把“尝试移动”和“正式更新”分开。只有候选位置合法时才同时更新 x、y，越界时自然保留旧状态。规则较多时，这比边判断边修改更不容易出错。

复杂模拟先做“统一表示”

统一单位时间统一换成秒，方向统一编号为 0—3，坐标统一采用同一种下标规则，减少分类讨论。
拆出单步函数把“一次操作”写成独立函数；主流程只负责按顺序调用，更容易单独测试。
维护不变量写下每步结束后始终成立的条件，例如位置一定在网格内、余额不能为负，并在调试时检查。

模拟题最常见的四类错误

①

状态漏记

只记录当前位置，却忘记方向、剩余次数等会影响下一步的数据。

②

顺序写反

题目要求“先扣费再判断”，代码却先判断后扣费，结果会完全不同。

③

边界差一

混淆下标从 0 还是从 1 开始，或把 < 写成 <=。

④

输出时机错误

题目要最终状态，却在每一步输出；或者需要记录过程，却只保存最终答案。

能模拟，不代表逐步模拟一定来得及

如果操作次数只有 10^5，逐步执行通常没有问题；如果题目要求执行 10^18 次，就要寻找周期、公式或批量处理方法。先看数据范围，再决定是否真的一步一步做。

FOUNDATION 05 · 做出当前最优选择

贪心

贪心算法会按照某条规则不断做出当前选择，并且不回头修改。代码往往只有“排序 + 遍历”，但真正的难点是找到正确规则，并说明这个局部选择为什么一定能组成全局最优答案。

贪心不是“每次挑最大的”

“最大、最小、最早、最短”都只是候选策略。只有能够通过证明，并且找不到反例的策略，才能称为正确的贪心算法。

01

明确优化目标

到底是让数量最多、总代价最小、等待时间最短，还是让剩余空间最大？

02

提出局部规则

思考当前选谁会给未来留下更有利的局面，而不是只看眼前数值大小。

03

先攻击自己的策略

构造 3—5 个元素的小数据，专门寻找能让策略失败的反例。

04

给出正确性理由

常用交换论证：把某个最优解的第一步换成贪心选择，答案不会变差。

经典例子：选择最多不重叠区间

学校只有一间教室，有 n 个活动申请使用。第 i 个活动的开始和结束时间分别是 lᵢ、rᵢ。选中一个活动，就必须按原定时间完整举行。请从这些活动中选出尽可能多的活动，使教室在任意时刻最多被一个活动占用。

活动占用半开区间 [lᵢ, rᵢ)，即从开始时刻占用教室，在结束时刻腾出教室。按实际举行顺序看，只要后一个活动的开始时间大于或等于前一个活动的结束时间，两者就能连续安排。例如 [2, 3) 和 [3, 5) 可以都选，[2, 3) 和 [1, 4) 会冲突。

输入格式

第一行输入整数 n。接下来 n 行，每行输入两个整数 lᵢ rᵢ，表示一个活动的开始时间和结束时间。活动可以按任意顺序给出。

输出格式

输出一个整数，表示最多能安排的活动数量。

数据范围

1 ≤ n ≤ 2 × 10⁵，0 ≤ lᵢ < rᵢ ≤ 10⁹。

样例中的一组安排

依次选择 [2, 3)、[3, 5)、[5, 6) 和 [6, 8)，能安排 4 个活动。

样例

输入
6
1 4
6 8
2 3
4 7
5 6
3 5
输出
4

先选哪个活动？

最早开始？可能很早开始、很晚结束，一次占满几乎所有时间。
持续最短？短活动可能卡在中间，同时挡住前后两个活动。
最早结束 ✓结束越早，为所有尚未选择的活动留下的时间越多。

手算选择过程

把样例中的 6 个活动按结束时间从小到大排序。每次只比较当前活动的开始时间与上一个已选活动的结束时间。跳过冲突的活动时，已选活动的结束时间保持原样。

当前区间上次结束是否选择原因
[2, 3)无选择第一个结束的活动
[1, 4)3跳过1 < 3，发生冲突
[3, 5)3选择3 ≥ 3，可以衔接
[5, 6)5选择5 ≥ 5，可以衔接
[4, 7)6跳过4 < 6，发生冲突
[6, 8)6选择6 ≥ 6，可以衔接

完整代码

interval_greedy.cpp
#include <bits/stdc++.h>
using namespace std;

struct Activity {
    long long l, r;
};

bool cmp(const Activity &a, const Activity &b) {
    if (a.r != b.r) return a.r < b.r;
    return a.l < b.l;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<Activity> a(n);
    for (Activity &e : a) {
        cin >> e.l >> e.r;
    }

    // 优先选择结束最早的区间，给后面留出更多空间
    sort(a.begin(), a.end(), cmp);

    int ans = 0;
    long long ed = LLONG_MIN;
    for (const Activity &e : a) {
        // 开始时间不早于上一个已选活动的结束时间
        if (e.l >= ed) {
            ans++;
            ed = e.r;
        }
    }
    cout << ans << '\n';
}
①

按结束时间排序让最早结束的可选活动最先被考虑。

②

ed记录最后一个已选活动的结束时间，用于判断冲突。

③

总复杂度排序是 O(n log n)，之后遍历一次是 O(n)。

为什么“最早结束”一定正确？

设贪心选择的第一个活动是 A，任意一个最优方案选择的第一个活动是 B。因为 A 是所有活动中结束最早的，所以 A 的结束时间不会晚于 B。

最优方案先选 B→用 A 替换 B→A 结束得更早→后续活动仍然都能安排

替换之后，活动数量没有减少，而且方案仍然合法。因此一定存在一个“第一步选择 A”的最优方案。对剩余活动重复同样的推理，贪心选择就能得到全局最优答案。这就是一个完整的交换论证。

交换论证把任意最优解中的某一步换成贪心选择，证明可行性不变且答案不会更差。
归纳 / 始终领先证明完成前 k 步后，贪心方案至少不劣于任何其他方案，再推进到第 k + 1 步。
无法证明怎么办把选择后剩余的问题写出来；若未来还需要比较多种历史状态，通常应考虑 DP，而不是强行贪心。

用反例排除看似合理的策略

错误策略

每次选择持续时间最短的活动。

反例

[0,5)、[4,6)、[5,10)。

贪心结果

选择最短的 [4,6) 后，另外两个都不能选，答案为 1。

真正最优

选择 [0,5) 和 [5,10)，答案为 2。

一种题能贪心，不代表相似题也能照搬

例如硬币面值为 1、3、4，凑出 6。每次拿最大硬币会得到 4 + 1 + 1，共 3 枚；最优方案是 3 + 3，只需 2 枚。局部最优没有自动保证全局最优。

□ 优化目标到底是什么？
□ 我的局部选择为未来保留了什么优势？
□ 能否构造小数据推翻它？
□ 能否用交换或替换说明答案不会变差？

FOUNDATION 02 · 程序能否按时完成

时间复杂度

时间复杂度描述输入规模 n 增大时，程序操作次数增长得有多快。它不直接等于运行秒数，而是帮助我们在写代码之前判断算法是否可能超时。

O(1)常数直接计算
→
O(log n)对数二分查找
→
O(n)线性遍历数组
→
O(n log n)线性对数高效排序
→
O(n²)平方两层枚举

怎样从代码看出复杂度？

O(1)执行次数与 n 无关
int answer = a[0] + a[n - 1];
O(n)一层循环执行 n 次
for (int i = 0; i < n; i++)
    sum += a[i];
O(n²)两层循环各执行约 n 次
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        check(i, j);

四条推导规则

顺序执行：相加O(n) + O(m) = O(n + m)，不要在有两个输入规模时强行写成 O(n)。
嵌套执行：相乘外层 n 次、每次内层 m 次，总计 O(nm)。
分支：看最坏情况竞赛题通常分析最坏时间；if 的两个分支取增长更快的一边。
规模反复减半n → n/2 → n/4，直到 1，次数为 O(log n)。

大 O 保留增长速度

3n² + 5n + 20 写作 O(n²)：忽略常数和低阶项，是为了描述 n 增大后的主导趋势。但两种同为 O(n) 的程序，常数、缓存访问和实现方式仍会影响真实速度。

根据数据范围估计算法

输入规模 n通常可以考虑直观理解
n ≤ 20指数级、状态枚举可以尝试枚举许多组合
n ≤ 500O(n³)三层循环需要谨慎

n ≤ 10⁵O(n log n) 或 O(n)排序、二分、线性遍历

估算不是绝对规则

实际速度还受到常数、语言、内存访问和评测机影响。竞赛中常用“约一秒执行一亿次简单操作”进行粗略判断，但不能把它当成精确保证。

FOUNDATION 03 · 程序需要多少内存

空间复杂度

空间复杂度描述算法额外使用的存储空间怎样随输入规模增长。数组、容器、递归调用栈都会占用内存；超过题目的内存限制会得到 MLE。

单个变量O(1)

无论 n 多大，只使用固定数量的变量。

int sum, maximum;
一维数组O(n)

保存 n 个同类型元素，空间随 n 线性增长。

vector<int> a(n);
二维数组O(n²)

保存 n × n 个元素，n 增大时内存增长很快。

int grid[n][n];

把元素数量换算成内存

常见的 int 通常占 4 字节，long long 通常占 8 字节。估算数组内存时，可以使用：

数组内存元素个数 × 每个元素的字节数

int a[1'000'000] 大约占用 1,000,000 × 4 B ≈ 3.8 MB

256 MB 大约能保存6,700 万个 int实际程序还需要其他内存，不能把限制全部用满
10000 × 10000 的 int 数组约 381 MB在 256 MB 限制下会超出内存
i
原地算法

如果算法直接在输入数组上修改数据，只使用少量额外变量，它的额外空间可能是 O(1)。分析时要区分“输入本身占用的空间”和“算法额外申请的空间”。

别漏算这些空间

递归调用栈递归深度为 n 时，即使没有显式数组，也可能使用 O(n) 栈空间并触发栈溢出。
容器与副本vector 除元素外还有少量管理开销；按值传递大容器还会产生一份完整副本。
滚动数组若当前状态只依赖前一层，可以复用存储，把 O(nW) 空间降到 O(W)。
大数组放在哪里也重要

巨大的局部数组通常位于调用栈，可能在远未达到题目内存限制前就崩溃。竞赛中常用 vector 动态分配，或在确有固定上界时使用全局数组；无论哪种方式都要先计算字节数。

二分

二分利用单调性，每次检查中间位置并排除一半范围。本节分为两部分：二分查找在有序数组中寻找数值或边界；二分答案在可能的答案范围中寻找最优可行值。

01 · 二分查找

当数组已经有序时，可以通过比较 a[mid] 与目标值，排除不可能包含目标的一半元素。每次查询的时间复杂度为 O(log n)；如果需要先排序，还要另计 O(n log n) 的预处理时间。

示例：在有序数组中寻找 13

下标1234567
数值25813172130

第 1 次：l = 0, r = 8, m = 4

检查 a[4] = 13；模板继续收缩边界，以统计小于和小于等于 13 的元素数。

模板写法：统计小于、等于和大于目标值的个数

数组使用 1…n 下标。沿用模板的 calc(x) 与 calc2(x)：分别找到最后一个小于 x、最后一个小于等于 x 的位置。记为 y、z 后，三类元素个数依次是 y、z-y、n-z；判断 x 是否存在只需检查 z-y > 0。

输入 n、查询数 m、n 个数组元素，再输入 m 个目标值；每次输出“小于、等于、大于”的三个计数。数组先排序，每次查询做两次二分。

binary_search.cpp
#include <bits/stdc++.h>
using namespace std;

int n;
vector<int> a;

// 返回最后一个小于 x 的位置，也就是小于 x 的元素个数
int calc(int x) {
    int l = 0, r = n + 1;
    while (l + 1 < r) {
        int m = l + (r - l) / 2;
        if (a[m] < x) l = m;
        else r = m;
    }
    return l;
}

// 返回最后一个小于等于 x 的位置
int calc2(int x) {
    int l = 0, r = n + 1;
    while (l + 1 < r) {
        int m = l + (r - l) / 2;
        if (a[m] <= x) l = m;
        else r = m;
    }
    return l;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int m;
    cin >> n >> m;
    a.resize(n + 1);
    for (int i = 1; i <= n; i++) cin >> a[i];
    sort(a.begin() + 1, a.end());
    while (m--) {
        int x;
        cin >> x;
        int y = calc(x), z = calc2(x);
        cout << y << ' ' << z - y << ' ' << n - z << '\n';
    }
    return 0;
}
①

l = 0, r = n + 1两个位置是虚拟哨兵，不读取 a[0] 或 a[n+1]；真实元素始终在开区间 (l, r) 中接受检查。

②

l + 1 < r两端之间还有元素时继续；使用 l + (r-l)/2 避免 l+r 相加溢出。

③

满足条件更新 l，否则更新 r结束时 l 是最后一个满足条件的位置；没有满足元素时 l=0，全部满足时 l=n。

竞赛更常用：寻找第一个满足条件的位置

同样使用模板的开区间写法：左端 l 是不满足条件的虚拟位置，右端 r 是满足条件的虚拟位置，只检查中间的真实位置。函数返回第一个 true；数组搜索时传入 l=0, r=n+1，返回 n+1 表示不存在，不能直接访问该位置。

first_true.cpp
template<class Check>
int firstTrue(int l, int r, Check check) { // 搜索开区间 (l, r)
    while (l + 1 < r) {
        int m = l + (r - l) / 2;
        if (check(m)) r = m; // r 维护满足条件的一侧
        else l = m;         // l 维护不满足条件的一侧
    }
    return r;
}

直接使用标准库边界函数

binary_search只返回 bool，判断 x 是否存在，不返回下标。
lower_bound返回第一个 大于等于 x 的位置；若不存在，返回 end()。
upper_bound返回第一个 严格大于 x 的位置；两者之差就是 x 的出现次数。
前提搜索区间必须按相同规则排好序；在 vector 上查询是 O(log n)。

02 · 二分答案：把最优化变成判定

有些题没有一个已经排好序的数组，而是要求“最小的可行上限”或“最大的可行下限”。这时可以二分答案的数值：先猜一个 mid，再写 check(mid) 判断这个答案是否可行。

猜一个答案 mid→用 check(mid) 判断能否做到→利用单调性保留一半范围→找到可行边界

完整例题：最小化最大分组和

给定 n 个非负整数，在保持原顺序的前提下，把它们分成至多 k 个非空连续段，使所有段中最大的段和尽可能小。设 1 ≤ k ≤ n ≤ 2 × 10⁵，0 ≤ a[i] ≤ 10⁹。

二分什么？二分每段和允许达到的上限 x。下界是最大元素，上界是整个数组的总和；关键是保证搜索区间包含答案。
怎样判定？从左到右贪心装入当前段，只有再放一个数会超过 x 时才新开一段。最后所需段数不超过 k，就说明可行。
为什么单调？上限 x 可行时，原来的分组在更大上限下仍然可行，因此 check(x) 呈 false → true，我们寻找第一个 true。

为什么这个 check 正确？

固定上限后，因为元素非负，每段尽量向右延伸，只会给后面留下更短的后缀。任何合法分组的第一段都不能比贪心第一段更靠右；对剩下的后缀重复这个理由，就能说明贪心使用的段数最少。因此贪心都需要超过 k 段时，其余分法也做不到。存在负数时，这个贪心判定不再适用。

例如 a = [7, 2, 5, 10, 8]，k = 2：上限为 17 时需要 [7, 2, 5] | [10] | [8] 三段，不可行；上限为 18 时可以分成 [7, 2, 5] | [10, 8] 两段，所以最优答案为 18。

binary_answer.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    cin >> n >> k;
    vector<long long> a(n);
    long long l = 0, r = 0;
    for (auto& x : a) {
        cin >> x;
        l = max(l, x); // 每个元素都必须放入某一段
        r += x;        // 整个数组作为一段一定可行
    }

    auto check = [&](long long mid) {
        int cnt = 1;
        long long sum = 0;
        for (long long x : a) {
            if (x > mid) return false;
            if (sum + x > mid) {
                ++cnt; // 当前段放不下，新开一段
                sum = x;
                if (cnt > k) return false;
            } else {
                sum += x;
            }
        }
        return true;
    };

    // 答案始终在闭区间 [l, r] 中，r 始终可行
    while (l < r) {
        long long mid = l + (r - l) / 2;
        if (check(mid)) r = mid; // mid 可行，继续尝试更小的上限
        else l = mid + 1;       // mid 不可行，更小的上限也不可行
    }
    cout << l << '\n';
    return 0;
}
①

输入与输出第一行输入 n 和 k，第二行输入 n 个非负整数；输出最小的最大段和。样例第一行输入 5 2，第二行输入 7 2 5 10 8，输出 18。

②

循环为什么结束？l < r 时，向下取整的 mid 严格小于 r；无论更新 r = mid 还是 l = mid + 1，区间都会缩小，最终 l = r 就是第一个可行值。

③

复杂度与整数范围设 S 为数组总和，一次 check 扫描 O(n)，总时间 O(n log(S + 1))，空间 O(n)。总和可能达到 2 × 10¹⁴，边界、mid 和累加器都要使用 long long。

最小可行值与最大可行值要分清

本例寻找 false → true 中的第一个 true。如果是“砍树高度尽量大”等题，check 往往呈 true → false，需要寻找最后一个 true，更新规则也要随之调整，不能原样照搬本例。

二分查找与二分答案的区别

二分查找搜索有序数组的下标，比较 a[mid] 与目标值；常见任务是查找元素、lower_bound 和 upper_bound。
二分答案搜索答案的取值范围，通过 check(mid) 判断可行性；总复杂度还需要乘上一次 check 的开销。
共同点先证明单调性，再确定搜索范围、区间含义、边界更新方式和无解时的处理。
二分最常见的错误

区间定义混乱。写代码前先决定使用哪种区间。本节查找模板用开区间 (l, r) 和 l+1<r，二分答案示例用闭区间 [l, r] 和 l<r，循环条件和更新方式必须始终与各自定义一致。

写二分前检查
□ 搜索的是具体数值、边界位置，还是答案？
□ 有序性或 check 的单调性已经证明了吗？
□ 区间定义、循环条件和更新规则一致吗？
□ 不存在答案时返回什么？
FOUNDATION 07 · 快速回答区间求和

前缀和

如果需要反复询问数组某个区间的元素总和，每次从左到右重新累加会很慢。前缀和先进行一次 O(n) 预处理，之后每次区间查询只需 O(1)。

前缀和数组表示什么？

定义 s[i] 表示原数组前 i 个元素之和。为了让公式更整齐，令 s[0] = 0。

原数组 a31415
逐项累加 ↓
s0348914
预处理公式s[i] = s[i - 1] + a[i]

把第 i 个元素加入前 i-1 个元素的总和。

区间 [l, r] 的和s[r] - s[l - 1]

前 r 个元素之和，减去 l 之前的所有元素。

为什么区间公式成立？

求数组第 2 到第 4 个元素之和：

3 + 1 + 4 + 1− 3= 1 + 4 + 1 = 6
s[4] - s[1] = 9 - 3 = 6
prefix_sum.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    vector<long long> a(n + 1), s(n + 1);
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        s[i] = s[i - 1] + a[i];
    }
    while (q--) {
        int l, r;
        cin >> l >> r;
        // 前 r 项减去 l 之前的所有项
        cout << s[r] - s[l - 1] << '\n';
    }
    return 0;
}

单次查询O(1)
q 次总时间O(n + q)
额外空间O(n)

前缀思想不只用于求和

令 s[i] 记录前 i 个元素中“满足条件的数量”，就能 O(1) 查询区间计数；把加法换成异或，还能得到区间异或值。能否相减消去前段，取决于所用运算是否具有对应的逆运算。

注意 long long

即使数组中的每个元素都能放进 int，许多元素相加后的前缀和也可能超过 int 范围。只要总和可能很大，就使用 long long。

EXTENSION · 从一条线推广到一个矩形

二维前缀和

二维前缀和用于快速计算矩阵中的矩形区域和。它是一维前缀和的自然推广：s[i][j] 表示从左上角 (1, 1) 到右下角 (i, j) 的整个矩形元素之和。

适用场景

多次询问矩阵中的矩形和

例如地图区域统计、二维棋盘计数、图片像素区域求和等。

12345 23456 34567 45678

怎样构造二维前缀和？

构造公式 s[i][j] = a[i][j] + s[i-1][j] + s[i][j-1] - s[i-1][j-1]

上方矩形与左方矩形都包含左上角重叠区域，因此相加后必须把 s[i-1][j-1] 减去一次。

①当前位置的值a[i][j]
②加上上方区域s[i-1][j]
③加上左方区域s[i][j-1]
④减去重复区域s[i-1][j-1]

怎样查询任意矩形？

设矩形左上角为 (x1, y1)，右下角为 (x2, y2)，包含边界。先取右下角的大前缀矩形，再减去上方和左方多余区域，最后把被重复减去的左上区域加回来。

矩形查询公式 s[x2][y2] - s[x1-1][y2] - s[x2][y1-1] + s[x1-1][y1-1]
取全部− 上方− 左方+ 重叠

下面沿用模板中的 a、s 和 query。输入 n、m、q，再输入 n 行 m 列矩阵，每次询问输入 x1、y1、x2、y2。固定数组版本适用于 1 ≤ n,m ≤ 1000；更大范围需要同时调整 N 并检查内存。

prefix_sum_2d.cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
const int N = 1005;
ll a[N][N], s[N][N];
int n, m, q;

// 查询矩形 (x1, y1) ~ (x2, y2)，包含边界
ll query(int x1, int y1, int x2, int y2) {
    return s[x2][y2] - s[x1 - 1][y2]
         - s[x2][y1 - 1] + s[x1 - 1][y1 - 1];
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n >> m >> q;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            cin >> a[i][j];
            // 上方加左方，减掉重叠，再加当前位置
            s[i][j] = s[i - 1][j] + s[i][j - 1]
                    - s[i - 1][j - 1] + a[i][j];
        }
    }
    while (q--) {
        int x1, y1, x2, y2;
        cin >> x1 >> y1 >> x2 >> y2;
        cout << query(x1, y1, x2, y2) << '\n';
    }
    return 0;
}
预处理时间O(nm)
单次查询O(1)
q 次总时间O(nm + q)
额外空间O(nm)
二维前缀和最容易错在下标

建议让矩阵下标从 1 开始，并额外保留第 0 行和第 0 列为 0。这样查询贴着上边界或左边界的矩形时，不需要额外分类讨论。

FOUNDATION 08 · 快速完成区间修改

差分

如果要对数组的许多区间整体加上一个数，逐个修改区间中的每个元素会很慢。差分只修改区间的两个边界，每次操作是 O(1)，最后再用一次前缀和还原整个数组。

差分数组表示什么？

令 d[i] = a[i] - a[i - 1]，并规定 a[0] = 0。差分记录的是“当前位置相对前一个位置变化了多少”。

原数组 a31415
相邻元素作差 ↓
d3-23-340

最后一个 0 是额外预留的 d[n + 1]，用于处理右端点恰好为 n 的区间修改。它不属于原数组。

构造差分d[i] = a[i] - a[i - 1]

记录相邻元素之间的变化量。

还原原数组a[i] = a[i - 1] + d[i]

对 d 求前缀和，就能重新得到 a。

区间 [l, r] 全部加上 k

从 l 开始增加 kd[l] += k

表示从位置 l 起，后面的元素都多出 k。

从 r + 1 取消影响d[r + 1] -= k

让这次增加只影响到 r，不继续传到后面。

原数组为 3 1 4 1 5，将区间 [2, 4] 全部加 2：

d[2] += 2d[5] -= 2还原后：3 3 6 3 5
区间内部不需要逐个修改，只改变开始位置和结束位置的下一格。

完整模板：多次区间加

沿用模板“读入 a → 构造 d → 修改两个端点 → 还原 a”的顺序。原模板每次区间加 1；这里把增量读为 k，以覆盖已有例题中的正数和负数修改。第一行输入 n、q，每次操作输入 l、r、k。

difference.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    // 多留一格给 d[r+1]；long long 保存多次累加的结果
    vector<long long> a(n + 2), d(n + 2);
    for (int i = 1; i <= n; i++) cin >> a[i];
    for (int i = 1; i <= n; i++) d[i] = a[i] - a[i - 1];
    for (int i = 1; i <= q; i++) {
        int l, r;
        long long k;
        cin >> l >> r >> k;
        d[l] += k;
        d[r + 1] -= k;
    }
    // 对差分求前缀和，按模板还原到原数组 a
    for (int i = 1; i <= n; i++) a[i] = a[i - 1] + d[i];
    for (int i = 1; i <= n; i++) cout << a[i] << ' ';
    cout << '\n';
    return 0;
}

单次区间修改O(1)
q 次修改并还原O(n + q)
额外空间O(n)
前缀和擅长“数组不变，多次查询区间和”。
差分擅长“多次修改区间，最后得到整个数组”。
两者关系差分的前缀和是原数组，原数组的相邻差是差分。
记得为 r + 1 多开一个位置

如果数组使用 1 到 n 的下标，差分数组至少开到 n + 1。代码中常写 vector<long long> d(n + 2)，避免访问 d[r + 1] 时越界。

普通差分适合离线得到最终结果

如果每次修改后都要立刻查询当前区间和，不能每次重新还原数组；这类在线问题通常需要树状数组或线段树。

EXTENSION · 从区间修改推广到矩形修改

二维差分

二维差分可以把矩形 (c1, d1) 到 (c2, d2) 内的所有元素同时加上 k。沿用模板，原矩阵记为 a，二维差分记为 b；一次修改只改变四个角，最后用二维前缀和还原 a。

矩形修改公式 b[c1][d1] += k　　b[c2+1][d1] -= k
b[c1][d2+1] -= k　b[c2+1][d2+1] += k

左上角开始产生影响，下方和右方分别取消影响，右下角因为被减了两次，需要再加回来一次。

完整程序先输入 n、m、q 和 n 行 m 列初始矩阵；每次修改输入 c1、d1、c2、d2、k，最后输出修改后的矩阵。两个矩阵均额外预留一行一列，以处理右边界和下边界。

difference_2d_update.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m, q;
    cin >> n >> m >> q;
    vector<vector<long long>> a(n + 2, vector<long long>(m + 2));
    vector<vector<long long>> b(n + 2, vector<long long>(m + 2));
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) cin >> a[i][j];
    }
    // 用原矩阵构造二维差分
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            b[i][j] = a[i][j] - a[i][j - 1]
                    - a[i - 1][j] + a[i - 1][j - 1];
        }
    }
    while (q--) {
        int c1, d1, c2, d2;
        long long k;
        cin >> c1 >> d1 >> c2 >> d2 >> k;
        b[c1][d1] += k;
        b[c1][d2 + 1] -= k;
        b[c2 + 1][d1] -= k;
        b[c2 + 1][d2 + 1] += k;
    }
    // 按从上到下、从左到右的顺序还原 a
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            a[i][j] = b[i][j] + a[i][j - 1]
                    + a[i - 1][j] - a[i - 1][j - 1];
        }
    }
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) cout << a[i][j] << ' ';
        cout << '\n';
    }
    return 0;
}

PART 01 · 概率是在数哪些可能结果

先建立样本空间，再谈事件概率

一次随机过程所有可能出现的基本结果组成样本空间。如果这些结果等概率，事件 A 的概率就是“满足 A 的结果数 ÷ 所有结果数”。例如公平骰子出现偶数，对应结果是 2、4、6，因此概率为 3 / 6 = 1 / 2。

条件概率的乘法公式P(A ∩ B) = P(A) · P(B | A)

P(B | A) 表示在 A 已经发生的条件下，B 再发生的概率。不要把两个阶段都机械地写成原来的分母。

独立事件：条件概率可以简化

若 A、B 独立，A 是否发生不改变 B 的概率，因此 P(B | A) = P(B)，乘法公式化为 P(A ∩ B) = P(A) · P(B)。前面的不放回抽球会改变袋中组成，不能直接套用独立事件公式。

PART 02 · 期望不是“一次会出现的答案”

期望表示大量重复试验后的长期平均

离散随机变量 X 可能取值 x₁, x₂, …，对应概率为 p₁, p₂, …，那么每个结果按出现概率加权：

离散随机变量的期望E[X] = Σ xᵢ · pᵢ

公平骰子的期望是 (1+2+3+4+5+6) / 6 = 3.5。骰子不可能掷出 3.5，它描述的是重复许多次后的平均点数。

期望值不一定是随机变量能取到的值

“期望为 1.2 次”不代表某一次会发生 1.2 次。一次结果仍然是整数，1.2 只描述很多次试验的平均水平。

PART 03 · 线性期望：先拆贡献，再分别计算

最重要的性质不要求随机变量彼此独立

期望的线性性E[X + Y] = E[X] + E[Y]

X、Y 即使互相影响，这个等式仍然成立。

0-1 指示变量I ∈ {0,1} ⇒ E[I] = P(I=1)

事件发生贡献 1，不发生贡献 0，期望正好等于发生概率。

!
“不独立”不等于“不能拆期望”

独立性会影响乘积或联合概率的计算，但 E[X₁ + X₂ + …] = E[X₁] + E[X₂] + … 始终成立。随机排列中的不同逆序对并不独立，仍然可以逐对计算贡献。

PART 04 · 首步分析：先支付这一步，再看下一状态

“到终点还要多少期望步数”通常是一组状态方程

令 f[u] 表示从状态 u 出发到结束的期望代价。站在 u 时先发生一次操作，付出当前代价；之后以不同概率进入下一状态 v：

期望 DP / 首步分析f[u] = cost[u] + Σ P(u→v) · f[v]

如果一次操作的代价就是 1，最前面一定有一个 1。终止状态不再需要操作，所以通常令 f[target] = 0。

先区分两个链上随机游走模型

若 0 与 n 都是吸收端点，从 i 等概率向左右走，令 p[i] 为先到 0 的概率，则 p[0]=1、p[n]=0，中间满足 p[i]=(p[i-1]+p[i+1])/2，所以 p[i]=(n-i)/n；先到 n 的概率是 i/n。下面的期望模型把 0 改为只能向右的反射端点，两个模型的边界条件不同。

例题：一维随机游走为什么得到 n²？

位置为 0,1,…,n，从 0 出发；中间位置等概率向左或向右一步，到达 n 后停止；在 0 不能向左，只能走到 1。设 f[i] 为从 i 到 n 的期望步数。

0只能向右↔1各 1/2↔2各 1/2…nf[n]=0
中间位置f[i] = 1 + ½f[i-1] + ½f[i+1]

先走一步，再按两种方向的概率加权。

左端点f[0] = 1 + f[1]

在 0 没有随机选择，只能走到 1。

作差d[i] = f[i-1] - f[i]

方程可化为 d[i+1] = d[i] + 2。

累加f[0] = 1+3+…+(2n-1) = n²

由 d[1]=1 得到连续奇数。

模板中的一般解f[i] = n² − i²

从 i 开始，累加 d[i+1] 到 d[n]，得到 f[i]=(2i+1)+(2i+3)+…+(2n-1)=n²-i²。代入 i=0 得 n²，代入 i=n 得 0，与两个边界一致。

这不是普通的“从左往右填表”

f[i] 同时依赖 f[i-1] 和 f[i+1]，依赖关系有环，本质是一组线性方程。这里利用一维结构作差化简；更一般的题可能需要移项、树形递推或高斯消元。

#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    vector<vector<int>> g(n + 1);  // 保存每个状态的后继
    while (m--) {
        int u, v;
        cin >> u >> v;  // 题目保证 u < v，因此没有环
        g[u].push_back(v);
    }

    // f[u] 表示从 u 出发的期望步数，终点 f[n] = 0
    vector<long double> f(n + 1, 0);
    for (int u = n - 1; u >= 1; u--) {
        int d = (int)g[u].size();  // 出边数量
        if (d == 0) continue;  // 没有出边就已经结束

        // 先走一步，再加上各后继状态的期望
        f[u] = 1;
        for (int v : g[u]) {
            f[u] += f[v] / d;  // 每条出边的概率都是 1/d
        }
    }

    cout << fixed << setprecision(6) << f[1] << '\n';
    return 0;
}

PART 05 · 小数答案与取模分数不是一回事

题目要求模质数时，用逆元表示除法

如果答案是分数 a/b，题目要求对质数 p 取模，且 b 不被 p 整除，就把除以 b 改写成乘以 b 的模逆元：a / b ≡ a · b^(p-2) (mod p)。沿用模板的 quickpow(a,n)，固定 p=1000000007，并先把底数规范到 [0,p)。若模数不是质数，应使用扩展欧几里得等方法，不能直接套 p-2。

#include <bits/stdc++.h>
using namespace std;
const int p = 1000000007;

long long quickpow(long long a, long long n) {
    a = (a % p + p) % p;
    long long ans = 1;
    for (; n; n >>= 1) {
        if (n & 1) ans = ans * a % p;
        a = a * a % p;
    }
    return ans;
}

int main() {
    long long a, b;
    cin >> a >> b;
    a = (a % p + p) % p;
    b = (b % p + p) % p;
    // p 是质数；b 能被 p 整除时没有逆元
    if (b == 0) {
        cout << "No inverse\n";
        return 0;
    }
    cout << a * quickpow(b, p - 2) % p << '\n';
    return 0;
}

例题：不相邻元素最大和

给定长度为 n（n ≥ 1）的整数数组，可以选择若干元素，但不能选择两个相邻元素。允许一个元素都不选，求所选元素之和的最大值。

状态定义

dp[i] 表示只考虑前 i 个元素时，可以获得的最大和。

不选第 i 个

答案保持为 dp[i - 1]。

选择第 i 个

第 i - 1 个不能选，答案为 dp[i - 2] + a[i]。

转移方程

dp[i] = max(dp[i-1], dp[i-2] + a[i])。

先把样例递推出来

数组为 [2, 7, 9, 3, 1]。设 dp[0] = 0，逐个比较“选当前”和“不选当前”。

i / a[i]不选：dp[i-1]选择：dp[i-2]+a[i]dp[i]
1 / 200 + 2 = 22
2 / 720 + 7 = 77
3 / 972 + 9 = 1111
4 / 3117 + 3 = 1011
5 / 11111 + 1 = 1212

完整代码

linear_dp.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    // a[i] 是第 i 个位置的收益
    vector<long long> a(n + 1);
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
    }

    // dp[i] 表示前 i 个位置中，不选相邻位置的最大收益
    vector<long long> dp(n + 1, 0);
    dp[1] = max(0LL, a[1]);

    for (int i = 2; i <= n; i++) {
        // 不选 i，或选 i 并跳过 i-1
        dp[i] = max(dp[i - 1], dp[i - 2] + a[i]);
    }

    cout << dp[n] << '\n';
    return 0;
}

空间为什么可以优化到 O(1)？

计算 dp[i] 时只使用 dp[i-1] 和 dp[i-2]，更早的状态不会再次使用，因此只需保存最近两个值。

long long x = 0;                 // dp[i - 2]
long long y = max(0LL, a[1]); // dp[i - 1]

for (int i = 2; i <= n; i++) {
    // 先算新状态，再依次移动前两个状态
    long long z = max(y, x + a[i]);
    x = y;
    y = z;
}

两种常见的线性状态定义

前 i 个的答案dp[i] 包含前 i 个元素的整体最优值，答案常在 dp[n]，本节例题属于这一类。
必须以 i 结尾dp[i] 表示必须选择第 i 个元素的答案，例如最长上升子序列；最终答案通常是所有 dp[i] 的最大值。
多状态如果当前位置有“选 / 不选”“持有 / 不持有”等不同状态，可增加一维或分别维护多个数组。
“前 i 个最优”与“以 i 结尾最优”不能混用

前者允许第 i 个元素不参与答案，后者要求答案必须落在 i。状态定义只差几个字，转移和最终答案位置却会完全不同。

XCPC 模板中的最长上升子序列

沿用XCPC 模板命名：a[i] 保存第 i 个数，f[i] 表示必须以 a[i] 结尾的最长严格上升子序列长度。先令 f[i] = 1，再枚举所有 j < i，只在 a[i] > a[j] 时接到 j 后面。答案是所有 f[i] 的最大值，不能直接输出 f[n]；相等元素不能延长严格上升序列。

lis.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<int> a(n + 1), f(n + 1);
    for (int i = 1; i <= n; i++) cin >> a[i];

    for (int i = 1; i <= n; i++) {
        f[i] = 1;  // 只选 a[i]，长度至少为 1
        for (int j = 1; j < i; j++) {
            if (a[i] > a[j]) {
                f[i] = max(f[i], f[j] + 1);
            }
        }
    }
    int ans = 0;
    for (int i = 1; i <= n; i++) ans = max(f[i], ans);
    cout << ans << '\n';
    return 0;
}

3 1 2 2 5 4
示例输出3

XCPC 模板中的最长公共子序列

输入两列整数，长度分别为 n、m。f[i][j] 表示 a 的前 i 个数与 b 的前 j 个数的最长公共子序列长度。先考虑跳过任意一列末尾的数；若 a[i] == b[j]，还可以把这两个数接在 f[i-1][j-1] 后。空前缀所在的第 0 行与第 0 列均为 0。

lcs.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    vector<int> a(n + 1), b(m + 1);
    vector<vector<int>> f(n + 1, vector<int>(m + 1));
    for (int i = 1; i <= n; i++) cin >> a[i];
    for (int j = 1; j <= m; j++) cin >> b[j];

    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            f[i][j] = max(f[i - 1][j], f[i][j - 1]);
            if (a[i] == b[j]) {
                f[i][j] = max(f[i][j], f[i - 1][j - 1] + 1);
            }
        }
    }
    cout << f[n][m] << '\n';
    return 0;
}

1 2 3 4
2 4 3
示例输出2

线性 DP 常见错误

①

状态含义不完整

只写“dp[i] 是最大值”，没有说明考虑范围以及是否必须选择 i。

②

转移来源漏掉

只考虑选择当前元素，忘记“不选当前”同样是一种合法决策。

③

初始化与题意冲突

不允许空方案时却把所有状态初始化为 0，会把不存在的方案当成合法答案。

④

答案取错位置

“必须以 i 结尾”的状态通常需要在所有 i 中取最优，而不一定直接输出 dp[n]。

DYNAMIC PROGRAMMING 02 · 在容量限制下做选择

背包 DP

背包问题研究“若干物品 + 一个容量限制 + 如何选择物品”。真正需要掌握的不是模板本身，而是状态表示、物品使用次数以及容量为什么要按特定方向遍历。

0/1 背包每件物品最多选择一次；一维优化后，容量必须从大到小遍历。
完全背包每件物品可以选择无限次；一维写法通常让容量从小到大遍历。
多重背包每件物品有指定数量，需要拆分、二进制优化或使用单调队列等方法。

0/1 背包模型

输入顺序按XCPC 模板保留：0/1 背包先读 m n，完全背包先读 n m；每件物品都读 v[i] w[i]。下面分别注明，复制时按对应格式输入。

有 n 件物品，第 i 件物品体积为 v[i]、价值为 w[i]，背包容量为 m。沿用XCPC 模板，v 表示占用容量，w 表示价值。每件物品只能选择 0 次或 1 次，求总体积不超过 m 时的最大总价值。

阶段

依次考虑前 1 件、前 2 件……前 n 件物品。

状态

f[i][j] 表示只考虑前 i 件物品、容量上限为 j 时的最大价值。

决策

第 i 件物品只有“不选”和“选择”两种情况。

答案

处理完全部物品后，答案是 f[n][m]。

从两种决策推导转移

不选第 i 件→f[i-1][j]　或　选择第 i 件→f[i-1][j-v[i]] + w[i]

当 j < v[i] 时装不下当前物品，只能不选；否则在两种决策中取最大值：

0/1 背包转移f[i][c] = f[i-1][c]　　　　　　　　　　　　(c < v[i])
f[i][c] = max(f[i-1][c], f[i-1][c-v[i]] + w[i])　(c ≥ v[i])

两种来源都在第 i - 1 行，因此同一件物品不会被重复使用。

二维写法：最容易理解

knapsack_2d.cpp
// f[i][j]：前 i 件物品、容量不超过 j 时的最大价值
vector<vector<long long>> f(
    n + 1, vector<long long>(m + 1, 0)
);

for (int i = 1; i <= n; i++) {
    for (int j = 0; j <= m; j++) {
        f[i][j] = f[i - 1][j];  // 不选第 i 件物品

        // 容量足够时，再尝试选择第 i 件物品
        if (j >= v[i]) {
            f[i][j] = max(
                f[i][j],
                f[i - 1][j - v[i]] + w[i]
            );
        }
    }
}

单次转移O(1)
时间复杂度O(nm)
空间复杂度O(nm)

压缩成一维：容量必须倒序

第 i 行只依赖第 i - 1 行，可以复用同一个 f[j] 数组。为了让右侧的 f[j-v[i]] 仍然代表“没有处理当前物品”的旧值，容量必须从大到小更新。

knapsack_01.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> m >> n;  // 与模板一致：先容量，再物品数
    vector<int> v(n + 1);
    vector<long long> w(n + 1), f(m + 1, 0);
    for (int i = 1; i <= n; i++) cin >> v[i] >> w[i];

    for (int i = 1; i <= n; i++) {
        // 倒序枚举容量，保证每件物品只用一次
        for (int j = m; j >= v[i]; j--) {
            f[j] = max(f[j], f[j - v[i]] + w[i]);
        }
    }
    cout << f[m] << '\n';
    return 0;
}

为什么正序会错？

假设只有一件体积 2、价值 3 的物品，容量为 6。如果容量从小到大更新：

更新位置读取的旧状态得到结果发生了什么
j = 2f[0] = 0f[2] = 3第一次选择物品
j = 4f[2] = 3f[4] = 6同一轮再次使用当前物品
j = 6f[4] = 6f[6] = 9同一件物品被选择三次
0/1 背包倒序，完全背包正序

倒序读取的是上一轮保留下来的旧状态，保证当前物品最多使用一次；正序会读取本轮刚更新的新状态，因此允许继续使用当前物品。

完全背包：同一件物品可以重复使用

完全背包仍可使用一维 f[j]，但容量从小到大更新。这样 f[j-v[i]] 可能已经在本轮加入当前物品，继续转移正好表示再次选择它。

complete_knapsack.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;  // 完全背包模板：先物品数，再容量
    vector<int> v(n + 1);
    vector<long long> w(n + 1), f(m + 1, 0);
    for (int i = 1; i <= n; i++) cin >> v[i] >> w[i];

    for (int i = 1; i <= n; i++) {
        // 正序枚举容量，允许当前物品重复使用
        for (int j = v[i]; j <= m; j++) {
            f[j] = max(f[j], f[j - v[i]] + w[i]);
        }
    }
    cout << f[m] << '\n';
    return 0;
}
0/1：容量倒序右侧读取上一轮状态，阻止同一件物品在本轮重复进入答案。
完全：容量正序右侧允许读取本轮新状态，从而继续使用当前物品。
循环不能随便交换求最值时物品在外、容量在内最清晰；求方案数时交换循环还可能改变“组合 / 排列”的含义。

“不超过容量”与“恰好装满”初始化不同

不超过容量允许什么都不选，通常把所有 f[j] 初始化为 0，最后读取 f[m]。
恰好装满只有 f[0] = 0 合法，其他容量初始化为负无穷，表示暂时不可达。
方案计数若求方案数，初始通常是 f[0] = 1，转移使用加法而不是取最大值。

DYNAMIC PROGRAMMING 03 · 先算儿子，再合并到父亲

树形 DP

在线性 DP 中，我们沿着数组从左到右计算；到了树上，节点会同时分出多个方向，应该先算谁就不再显然。树形 DP 做的第一件事，就是把无向的树整理成“父亲依赖儿子”的计算结构，再把每棵小子树的答案一层层向上合并。

PART 01 · 先弄清计算顺序

第一步：把树“有根化”

如果输入直接说明“父亲是谁”，可以只保存父亲到儿子的有向边；如果输入只是 n - 1 条无向边，就要双向加边，并在 DFS 中跳过父亲。无根树在题目没有特殊要求时通常可任选 1 号节点为根。

父子输入

fa child 已经确定方向，只需 q[fa].push_back(child)。

无向边输入

同时加入 u → v 和 v → u，遍历时通过 fa 防止走回头路。

为什么选根

根只是在无向树上人为确定计算方向，不会改变树的边和连通关系。

完成顺序

一次 DFS 的完成顺序是叶子到根，恰好满足子状态先于父状态。

tree_dp_template.cpp
vector<vector<int>> q;  // 在读入 n 后初始化为 n + 1 个邻接表

void solve(int u, int fa) {
    // 1. 初始化 f[u]
    for (int v : q[u]) {
        if (v == fa) continue;
        solve(v, u);
        // 2. 使用已经算好的 f[v] 更新 f[u]
    }
}

当题目再增加人数限制：树形背包

普通舞会只关心“选不选 i”。如果再要求最多选择 m 个人，父亲合并儿子时还必须知道每棵子树分到几个名额。这里按XCPC 模板，把人数这一维定义为容量上限。

找到实际根 root，读取 max(f[root][m][0], f[root][m][1])。

j合并后允许使用的总名额
=
j-k此前已经合并部分的名额
+
k当前儿子 son 子树的名额

j、k 是人数上限，可以有空余，不要求必须用满。合并一个儿子时，i 不参加便可取儿子的两种状态的最大值；i 参加则只能取儿子不参加的状态。k = 0 的情况就是保留旧值，因此代码从 k = 1 开始。

#include <bits/stdc++.h>
using namespace std;

int n, m;
const long long NEG = -(1LL << 60);
vector<long long> v;
vector<int> fa;
vector<vector<int>> q;
vector<vector<array<long long, 2>>> f;

void solve(int i) {
    // 此时两列都只合并儿子的贡献，i 自己最后才占名额。
    for (auto son : q[i]) {
        solve(son);
        for (int j = m; j >= 0; j--) {
            for (int k = 1; k <= j; k++) {
                f[i][j][0] = max(f[i][j][0],
                    f[i][j - k][0] + max(f[son][k][0], f[son][k][1]));
                f[i][j][1] = max(f[i][j][1],
                    f[i][j - k][1] + f[son][k][0]);
            }
        }
    }
    // i 参加：预留一个名额给自己，其他名额只允许儿子不参加。
    for (int j = m; j >= 1; j--) f[i][j][1] = f[i][j - 1][1] + v[i];
    f[i][0][1] = NEG;  // 0 个名额不能让 i 参加
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n >> m;
    v.resize(n + 1);
    q.resize(n + 1);
    fa.assign(n + 1, 0);
    f.assign(n + 1, vector<array<long long, 2>>(m + 1, {0, 0}));
    // 沿用人数限制模板的输入顺序，同时记录父亲找实际根。
    for (int i = 2; i <= n; i++) {
        int x, y;
        cin >> x >> y;  // y 是 x 的上司
        q[y].push_back(x);
        fa[x] = y;
    }
    for (int i = 1; i <= n; i++) cin >> v[i];
    int root = 1;
    while (fa[root]) root = fa[root];
    solve(root);
    cout << max(f[root][m][0], f[root][m][1]) << '\n';
    return 0;
}

    b[i] = true;
    for (auto j : q[i]) {
        if (!b[j]) {

PART 02 · 石子合并：枚举最后一次分界

题目模型

n 堆石子排成一行，每次只能把相邻两堆合并，代价等于两堆石子的总数。要求把所有石子合成一堆的最小总代价。对于 1、2、10：

先合并 1 与 21 + 2 = 33 + 10 = 13总代价 16
对比
先合并 2 与 102 + 10 = 121 + 12 = 13总代价 25
状态定义

f[l][r]

把第 l 堆到第 r 堆全部合并成一堆的最小代价。

最小区间

f[i][i] = 0

一堆石子本来就是一堆，不需要发生合并。

不要从“第一步合并什么”想，要从“最后一步剩什么”想

当 [l,r] 最终合成一堆时，最后一次合并之前一定恰好剩下两堆连续石子。它们可以写成 [l,k] 和 [k+1,r]，其中 k 从 l 枚举到 r-1。

[ l ... r ]最后一次合并前
[ l ... k ]+[ k+1 ... r ]
最后再付出整段石子总数
石子合并转移f[l][r] = min(f[l][k] + f[k+1][r] + sum(l,r))

前两项分别是把左右两段各自合成一堆的最小代价；最后一项是把这两大堆合起来时必付的代价。

用前缀和 O(1) 求区间石子总数

按XCPC 模板，状态数组统一写成 f；公式仍用 l、r 讲解区间，代码中用 i 表示长度、j 表示左端点，所以 l = j、r = j + i - 1，k 仍是分界点。

s[i] = a[1] + … + a[i]→sum(l,r) = s[r] - s[l-1]

如果每次转移都重新循环求 sum(l,r)，会在三层枚举外又增加一层计算。前缀和让区间代价保持 O(1)。

为什么只枚举 k 就不会漏？

无论前面怎样合并，最后一刻一定只剩左右相邻的两大堆。它们之间必有且只有一条分界线 k。枚举 l ≤ k < r 就枚举了所有可能的最后一步；左右两段内部的最佳合并方式已经分别保存在两个较短状态中。

#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    vector<long long> a(n + 1), s(n + 1, 0);
    for (int i = 1; i <= n; i++) cin >> a[i];
    for (int i = 1; i <= n; i++) s[i] = s[i - 1] + a[i];

    const long long INF = (1LL << 60);
    vector<vector<long long>> f(n + 1, vector<long long>(n + 1, INF));
    for (int i = 1; i <= n; i++) f[i][i] = 0;

    // i 枚举区间长度，j 枚举左端点。
    for (int i = 2; i <= n; i++) {
        for (int j = 1; j + i - 1 <= n; j++) {
            // 枚举最后一次合并的分界 k。
            for (int k = j; k <= j + i - 2; k++) {
                f[j][j + i - 1] = min(f[j][j + i - 1],
                    f[j][k] + f[k + 1][j + i - 1] + s[j + i - 1] - s[j - 1]);
            }
        }
    }
    cout << f[1][n] << '\n';
    return 0;
}

这次状态求的是最大值

括号模板也沿用 i、j、k 的枚举方式。字符串没有补空格，区间 [j,j+i-1] 的字符下标要分别减 1；f 多开两格，使长度为 2 时访问空区间仍合法。

给定只含 ( ) [ ] 的字符串，求最长合法括号子序列长度。子序列允许跳过字符，但不能改变相对顺序。例如 ([)] 不是合法括号串，却能选择 () 或 []，答案为 2。

子序列不等于子串

子串必须连续，子序列可以跳过若干字符。本题的 f[l][r] 表示在整个区间里“挑选”字符，因此不要求最终选出的字符在原串中连续。

状态定义

f[l][r]

字符串区间 [l,r] 中能选出的最长合法括号子序列长度。

最小区间

f[i][i] = 0

单个括号无法组成一对，空区间的答案也视为 0。

情况一：左右端点恰好能配成一对

(区间 [l+1, r-1] 的最优子序列)+ 2

如果区间的左右端字符是 () 或 []，可以把它们包在中间最优解两侧。DP 区间用 1-based 下标，代码里的字符串保留 0-based，因此 [l,r] 对应 s[l-1] 与 s[r-1]：

端点配对f[l][r] = max(f[l][r], f[l+1][r-1] + 2)

当区间长度为 2 时，中间是空区间，贡献为 0，所以一对匹配括号得到长度 2。

情况二：答案由两个合法子序列拼接

合法序列还可能像 (())[] 一样由两段组成，因此仍要枚举分界点 k：

区间拼接f[l][r] = max(f[l][r], f[l][k] + f[k+1][r])

k 从 l 到 r-1。这个转移也自然覆盖了“不使用左端点”或“不使用右端点”的情况，因为单字符区间贡献为 0。

#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    string s;
    cin >> n >> s;
    vector<vector<int>> f(n + 2, vector<int>(n + 2, 0));

    // DP 用 1-based 区间，字符串 s 保留 0-based 下标。
    for (int i = 2; i <= n; i++) {
        for (int j = 1; j + i - 1 <= n; j++) {
            // 区间 [j,j+i-1] 的两个字符是 s[j-1]、s[j+i-2]。
            if ((s[j - 1] == '[' && s[j + i - 2] == ']') ||
                (s[j - 1] == '(' && s[j + i - 2] == ')')) {
                f[j][j + i - 1] = f[j + 1][j + i - 2] + 2;
            }
            // 即使端点可配对，也要继续考虑分割。
            for (int k = j; k <= j + i - 2; k++) {
                f[j][j + i - 1] = max(f[j][j + i - 1],
                    f[j][k] + f[k + 1][j + i - 1]);
            }
        }
    }
    cout << f[1][n] << '\n';
    return 0;
}

PART 05 · 初始化、顺序与边界

初始化不是选择一种 memset，而是代入状态定义

求最小值f[l][r] = INF

先设为不可能的大值，再用每个合法候选不断取 min；基础状态单独赋值。

求最大值f[l][r] = 0

只有当“不选任何元素”是合法方案时，0 才能作为所有状态的初始下界。

单点区间f[i][i] = ?

把“只剩一个元素”代入定义：石子无需合并为 0，单括号无法配对也为 0。

提交前检查
□ 是否用一句完整的话定义了 f[l][r]？
□ len 是否从最短依赖开始递增？
□ 是否写成 r = l + len - 1？
□ 左端点循环是否保证 r ≤ n？
□ 分界点是否满足 l ≤ k < r？
□ 空区间与单点区间是否有明确含义？
□ 求最小值时，INF 与加法是否会溢出？
□ O(n³) 是否能通过题目的 n？
最常见的 off-by-one：把区间长度写成 r - l

闭区间 [l,r] 的长度是 r - l + 1，所以 r = l + len - 1。分界成 [l,k] 和 [k+1,r] 时，k 必须严格小于 r。

三名队员会同时阅读题目，但只有一人能够操作电脑。有人负责推导算法，有人检查边界和样例，有人把已经确认的思路写成代码。角色不是固定职业，而会根据题目和队员特长不断切换。
